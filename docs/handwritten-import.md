# 手書き予約表の取り込みと顧客リスト

電話や店頭で受けた予約を紙の予約表に書き、写真に撮って管理画面から登録する。
登録された予約と Web 予約から、顧客リストが自動で作られる。

---

## 全体の流れ

```
紙の予約表に手書き
  ↓ 写真を撮る（四隅の黒い四角が写るように、真上から）
管理画面「手書き予約の取り込み」で写真を選ぶ
  ↓ AI（Claude Opus 5）が読み取る（1〜2 分）
確認画面で 1 件ずつ確認・修正
  ├ 名前 → 顧客リストの候補から選ぶ（いなければ新規追加）
  └ 既存の予約と時間が重なる → ポップアップで解決方法を選ぶ
  ↓ 「登録する」
予約が登録され、顧客リストも更新される
```

読み取っただけでは何も登録されない。必ず人が確認してから登録する。

---

## 予約表（紙）

印刷用 PDF: 管理画面の取り込みページ上部「予約表（印刷用 PDF）」
（実体は `public/booking-sheet.pdf`。`python scripts/make_booking_sheet.py` で作り直せる）

- A3 縦・2 ページ。1 ページ目が予約表、2 ページ目が書き方とお客様メモ。
- 1 行 = 15 分、9:00〜19:30。横線は**すべて破線**で印刷してある。
- 予約が入ったら、その時間帯の上下の破線を**なぞって実線**にし、四角で囲む。
  四角の上辺 = 開始、下辺 = 終了。
- 1 日分の中は「開始」「名前」「コース」の 3 欄に固定。四角の最初の行に書く。
- メニューは記号で書く（C2、K1+剃 など）。凡例は 1 ページ目にある。
- 取り消しは四角の中に大きく ×。
- 新規のお客様は名前の横に ①②… を付け、2 ページ目のお客様メモに電話番号を書く。

### 横線をすべて破線にしている理由

毎正時の線だけでも実線で印刷すると、ペンでなぞった線と見分けがつかなくなり、
AI が予約の範囲を取り違える。1 時間ごとの目印は、線ではなく
「太字の時刻」と「薄い灰色の帯」で付けている。

### メニュー記号の変更

`src/lib/sheet/menu-codes.json` を直し、予約表 PDF を作り直す。
取り込み側も同じ JSON を読むので、コードの変更は不要。
料金は PDF 作成時に Supabase から読むので、料金改定のたびに作り直すと印刷物も新しくなる。

## 重複の扱い

登録前に、次の 2 種類の重複を調べる。

| 種類 | 例 |
| --- | --- |
| システムの予約との重複 | 手書きの 10:00〜 と、Web 予約の 10:15〜 が重なる |
| 同じ写真の中での重複 | 手書きの 2 行が同じ時間に重なっている（読み取りミスが多い） |

重複があると、読み取り直後と「登録する」を押したときにポップアップが出て、
行ごとに次を選ぶ。

| 変更対象 | 変更内容 |
| --- | --- |
| 手書きの予約 | 登録しない（同じ予約を二重に書いた・書き間違い） |
| 手書きの予約 | 日時を変更して登録 |
| システムの予約 | キャンセルして、手書きの予約を登録 |
| システムの予約 | 日時を変更して、手書きの予約を登録 |

- 同じお客様・同じ開始時刻の予約は「同じ予約の可能性大」と表示し、
  既定で「登録しない」にしている（Web 予約を紙にも書き写した場合など）。
- システムの予約を動かせるのは、重なっている相手が 1 件だけのとき。
- システムの予約をキャンセル・移動しても、お客様にメールは送らない。
  お店から直接連絡する運用。
- 最終的な二重予約は DB の制約（EXCLUDE）でも防いでいる。

## 顧客リスト

管理画面「顧客リスト」。

- Web 予約・手動登録・手書きの取り込み、どれで予約が入っても自動で追加・更新される
  （DB のトリガ。`supabase/migrations/20260921000001_customers.sql`）。
- 電話番号・メールが分からない欄は**黄色で「未登録」**と表示。
  「情報が足りない人だけ」で絞り込める。
- 顧客の詳細画面で電話番号・メールを入れると、これからの予約で連絡先が空のものにも反映される。

### 同じ人かどうかの判定

| 順 | 条件 | 判定 |
| --- | --- | --- |
| 1 | メールアドレスが一致 | 同じ人 |
| 2 | 電話番号と名前が両方一致 | 同じ人 |
| 3 | 名前が一致し、相手に連絡先が何も無い | 同じ人（手書きで名前だけ登録された人が、あとで Web 予約した） |
| 4 | どれにも当たらない | 新しい顧客 |

電話番号だけで同一人物にしないのは、家族で番号を共有している場合に
父と息子を同じ人にしてしまうため。既に入っている値は上書きせず、空欄だけ埋める。

### 手書きの名前からの特定

手書きは姓だけのことが多いので、取り込み画面では候補を出して人に選んでもらう。

- 電話番号（お客様メモ）が一致 → 最有力
- 名前が完全一致 → 有力
- 姓だけ一致 → 候補

最有力の候補が 1 人だけならそれを選んだ状態にし、迷う場合は「選んでください」にする。
候補がいなければ「新しいお客様として追加」になり、電話番号の欄は黄色になる。

## 設定

| 環境変数 | 内容 |
| --- | --- |
| `ANTHROPIC_API_KEY` | 必須。https://console.anthropic.com で発行 |
| `SHEET_EXTRACT_EFFORT` | 任意。既定 `high`。遅すぎる場合だけ `medium` |

Vercel の Environment Variables にも同じものを入れて Redeploy する。

### 料金の目安

Claude Opus 5（入力 $5 / 出力 $25 per 1M トークン）。
写真 2 枚の取り込み 1 回で 0.2〜0.4 ドル程度。週 1 回なら月 1〜2 ドル。

### 処理時間

読み取りに 1〜2 分かかることがある。取り込みページは `maxDuration = 300`（5 分）にしている。

## ダミーデータの後片付け

顧客リストのマイグレーションを流すと、動作確認用のダミー予約（`@dummy.example`）からも
顧客が作られる。ダミーを消すときは顧客もあわせて消す。

```sql
delete from public.reservation_items where reservation_id in (
  select id from public.reservations where customer_email like '%@dummy.example');
delete from public.reservations where customer_email like '%@dummy.example';
delete from public.customers where email like '%@dummy.example';
```
