# 予約ルール

2026-09 に決めたルール。**コードと DB の両方に同じ値がある**ので、変えるときは
必ず 2 か所そろえること。

| ルール | 値 | コード | DB |
| --- | --- | --- | --- |
| 予約できる期間 | 今日から 3 ヶ月先まで | `BOOKING_HORIZON_MONTHS` | `c_horizon` |
| 期間内に持てる予約 | 1 人 3 件まで | `MAX_RESERVATIONS_IN_HORIZON` | `c_max_in_horizon` |
| 予約どうしの間隔 | 前後 7 日以内は不可 | `MIN_GAP_DAYS_BETWEEN_RESERVATIONS` | `c_min_gap` |

- コード: [`src/lib/calendar.ts`](../src/lib/calendar.ts)
- DB: [`supabase/migrations/20260920000002_booking_limits.sql`](../supabase/migrations/20260920000002_booking_limits.sql)

## 判定の決めごと

**「1 人」はメールアドレスで見る。** 電話番号は家族で共有されることがあり、
父と息子を同じ人とみなして弾いてしまうため使っていない。
逆に、家族で 1 つのメールアドレスを使っている場合は同一人物として扱われる。
その場合はそれぞれ別のアドレスを入れてもらう案内を予約フォームに出している。

**数えるのは `pending` / `confirmed` の予約だけ。**
キャンセル済み・来店済み（`completed`）・無断キャンセルは数に入らない。
3 日前に来店した人が翌日を予約することは妨げない。「予約を何件も押さえたままにする」
のを防ぐのが目的なので、過去の来店実績は関係ない。

**「1 週間」は前後 7 日の移動窓。** カレンダー上の週（月曜〜日曜）ではない。
9/10 に予約がある人は 9/3〜9/17 の間を取れない。
暦の週で判定すると、日曜と翌月曜が別の週になって連日予約できてしまう。

**3 ヶ月は暦どおり。** 9/20 なら 12/20 まで。日数の固定値ではないので、
2 月をまたぐ場合も自然な結果になる。月末は丸める（11/30 → 2/28）。

## 上限に当たったときの表示

`create_reservation` が投げる例外を
[`src/app/(public)/reservations/new/actions.ts`](../src/app/\(public\)/reservations/new/actions.ts)
で日本語に直している。

| 例外 | 画面に出る文言の要旨 |
| --- | --- |
| `too_far_ahead` | ご予約は 3 ヶ月先までです |
| `too_many_reservations` | お一人さま 3 件までです |
| `too_soon_after_other` | ご予約の前後 7 日以内は取れません |

入力し終わってから弾かれると手間なので、お客様情報の入力画面にも
あらかじめルールを表示している。

## 管理画面からの手動登録は対象外

電話予約の記帳（`/admin/reservations/new`）は `create_reservation` を通さず
直接 INSERT しているため、これらの上限は掛からない。
店舗側は常連さんの予約をまとめて入れられる。意図的にそうしている。
